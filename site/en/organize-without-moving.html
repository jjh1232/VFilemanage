Organizing files without moving them — shortcuts, libraries and symlinks

You want things tidy, but moving a file quietly breaks something. There are four ways to group files in place, each good at a different job.

Why moving files hurts

The moment you create a folder and start dragging things into it to tidy up by topic, a few things break without saying anything.

  • Anything with a path baked in — project files from editors like Premiere, After Effects or Blender record where their source assets live. Move the assets and the next time you open the project, it reports missing files.
  • Recent-file lists — every one of them, in every program, goes dead.
  • Sync folders — pull a file out of OneDrive or Dropbox and it stops syncing. Push one in and it suddenly starts consuming your quota.
  • Backup rules — if your backup targets specific folders, a moved file drops out of the next run. You find out about that when you try to restore it.

So people give up and leave everything where it fell. But there are ways to group files without moving them.

Shortcuts (.lnk)

A one-kilobyte file that points at the original. Right-click to make one, drop it in any folder, double-click and the original opens.

Good for — a handful of items you keep on the desktop or in a working folder.

Where it stops — it does not scale. Open a folder full of shortcuts in Explorer and thumbnails often fail to render, and sorting by size or date sorts the shortcut files rather than the originals. If you move an original, Windows tries to track it, but that usually fails once a different drive or a rename is involved.

Windows libraries

These are the Documents and Pictures entries in Explorer's sidebar. A library merges several scattered folders into one view, and you can right-click it to add more folders.

Good for — grouping at the folder level, as in "show me the photos folder on D: and the one on my external drive together". It is built into Windows, needs nothing installed, and sorting, search and thumbnails all work against the real files.

Where it stops — it works on folders, not files. There is no way to say "just these three files out of that folder". Maintaining a set of topic-specific libraries also gets awkward fast.

Symbolic links and junctions (mklink)

These are filesystem-level entries that point at another path. The crucial difference from a shortcut is that programs treat them as the real file or folder. You create them from a command prompt.

  • mklink /J link target — a directory junction. The safest option for folders on the same PC, and it needs no administrator rights.
  • mklink /D link target — a directory symbolic link. It can point at network paths, but requires administrator rights.
  • mklink link target — points at a single file.

Good for — cases where a program insists the data live at a particular path. Relocating a game's save folder or a large cache directory to another drive is the classic use.

Where it gets dangerous — deletion. Deleting a junction in Explorer removes only the link, but some tools follow it and delete the contents of the original. Command-line deletes and older backup or sync software are the usual offenders. Backup tools also frequently count the original and the link separately and back the same data up twice. Powerful, but hard to recommend for everyday tidying.

When search is the answer

If the goal is simply opening one file whose name you know, search beats organizing. A filename indexer finds it across every drive instantly.

What search cannot do is represent "the set of things I look at often". That set is not written in any filename or folder; it exists only in your head, which is exactly the part you cannot type into a search box.

What VFilemanage does

VFilemanage does not touch the filesystem at all. It records where each original lives in a single database file and builds virtual folders inside the app.

  • Creating, moving and deleting folders inside the app does nothing whatsoever to the real files.
  • The same file can sit in several folders at once without using any extra disk space.
  • Double-clicking opens the original in whatever program is associated with it.
  • Everything you organize lives in filetree.db under %APPDATA%\VFilemanage. Copy that folder and the same library opens on another PC.

The limits are equally clear. This organization exists only inside the app. It does not appear in other programs' Open dialogs and it does not appear in Explorer. If an original is moved or deleted, the entry stays in the list but reports that the original cannot be found, and you can either relink it to its new location or remove it.
